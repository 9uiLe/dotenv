# Mac導入と共有設定の検証範囲

2026-10-20、macOS/Python 3.14でPC共通Gitフックを含む132件の自動テストが成功。模擬環境の配置済みランタイムによる通し確認30項目も成功している。さらに、承認を受けて個人用Macへ導入し、実際の設定保持・OS登録・停止・初期状態への復元・再導入を確認した。PC共通Git設定の実機反映は未実施。

## 確認できたこと

| 対象 | 検証内容 |
| --- | --- |
| 導入前の差分 | 設定を読み取るだけで、ランタイム・共有部分・日次設定の差分と照合データを私有フォルダへ出力 |
| 初回配布 | personal/work双方で共有ルール・スキル・Hook・実行処理を配置、既存設定を保持 |
| 配布ランタイム | checkoutとは別のディレクトリから子プロセスでstatus・sync・Hook・停止・再開を実行 |
| 日次更新 | 09:59は未実行、翌日10:00は反映、成功済み同日は重複なし、遅いログイン時刻で当日分を実行 |
| OS登録 | 専用LaunchAgentのbootstrap/bootout/printを模擬アダプターで確認。既存登録や状態不明なら初回導入を拒否 |
| 停止・再開 | 受信と共有Hookの停止は独立。更新再開でHookを勝手に再開しない |
| 旧版への復元 | プレビューは無変更、適用後は旧版へ戻して更新・共有Hook・OS登録を停止 |
| 導入取り消し・再導入 | 個別設定・既存Hook・バックアップを保持して共有ファイルを退避し、通常のGitHub受信・CI確認を経て再導入 |
| 設定・共有元の変化 | 差分作成後と適用直前の変更を検出して拒否 |
| CI成功の確認 | 一致するコミット・ブランチ・元リポジトリ・CI定義の最新実行だけ受理。待機・失敗・不正応答・API不通なら保持 |
| 登録失敗 | 更新停止を試み、停止まで失敗した場合も未確認として報告 |
| 読取・書込境界 | 本人の標準homeのみ、リンク・特殊ファイル・不適切な所有者/権限・私有計画の不正を拒否 |
| ランタイム改変 | 配置済みソースのハッシュが変わると更新とHook起動を拒否 |
| Codexの信頼記録 | `hooks.state`だけの設定をinline Hookと誤判定せず、導入後に信頼記録が増えても更新と記録保持が両立 |
| 障害・競合 | 受信失敗・履歴巻き戻し・途中書込障害・強制終了・排他ロックを旧版維持または復旧で処理 |

従来の模擬Git受信14項目、配布・停止・復元28項目も再現用デモとして残している。

## PC共通Gitフックの確認

隔離したホームのGit共通設定を使い、このリポジトリとは別のプロジェクトで実際の
`git commit` を行って確認した。ステージ済みblobの20,000／20,001バイト境界、
部分ステージ、ロックファイル・生成物の除外、日本語の分割手順を確認している。

既存のglobal・system・XDG設定、条件付きinclude、既定のリポジトリフック、
worktree、bareリポジトリ、初期化中のGitイベント、引数と標準入力の引き継ぎも確認した。
個別の `core.hooksPath` がある場合は個別設定が優先され、検査専用の起動ファイルから
再帰せず共通検査を呼び出せる。

導入差分はホームを変更せず、導入後はコピー済みランタイムだけで動作する。
共有版の更新・停止・旧版復元・取り外し、レビュー後の設定変更拒否、旧ランタイムからの
更新と途中失敗時の復元を自動テストで確認した。実際の各PCへの配布と共通設定の有効化は、
共有元の公開・CI成功と各PCでの受信後に確認する。

```sh
python3 -B -m unittest prototype.test_token_hook prototype.test_git_dispatch prototype.test_git_install prototype.test_runtime_upgrade -v
```

## 個人用Macでの実機確認

公開GitHubのmaster（コミット`019768305aa79600e36403e419c5eca5fdd197fa`）からサンプル共有元を受信し、そのCI成功を実際のGitHub APIで確認した。最初の読み取り専用の計画作成では設定の内容・更新時刻・権限・inodeと管理フォルダの有無が前後で一致した。その後、個人用の計画を承認して適用した。

| 対象 | 実機で確認した結果 |
| --- | --- |
| 既存設定 | 個人用の共有部分を追加し、既存のCodex設定とClaude設定を保持。Codex自身が追加した信頼記録と画面設定は保持 |
| 日次処理 | 10:00・ログイン時起動のLaunchAgentを登録。OS経由の手動起動が正常終了し、同日成功済みの重複更新を抑制 |
| 受信 | 最小限の実行環境で、配置済みランタイムからGitHub受信とCI成功確認が成功 |
| 停止・復元 | 更新と共有Hookの停止・再開、共有部分の取り外しによる導入前への復元、通常の再導入が成功。最終状態は更新・共有Hookとも有効 |
| Codex読み込み | モデル推論を行わず、入力に共有ルールとスキルが含まれることを確認。共有Hookだけを承認して信頼済み・有効として読み込むことを確認 |
| Hook処理 | 配置済み処理の直接実行で共有版を返し、停止中は何も追加しないことを確認 |

初回導入では前の共有版の履歴がないため、実機では`uninstall`による導入前への復元と`reinstall`を確認した。`restore`による前の共有版への復元は模擬環境で確認している。設定コピー・差分・計画・検証結果はGit対象外の私有フォルダだけに保存し、送信しない。

## 再現方法

```sh
python3 -B -m unittest discover -s prototype -p 'test_*.py' -v
python3 -B -m ai_knowledge.demo
```

生成した模擬ホームと結果は`.prototype/`に保存する。実際の設定の変更ではない。CIでは同じ試験をLinux/Python 3.11とmacOS/Python 3.14で実行する。送信済みCIの結果と、手元で変更中の実装の結果は区別する。

## 未確認の範囲

- 自然な10:00の定刻起動、ログイン後の起動とスリープ復帰。OS登録と手動起動は確認済みだが、自然な起動の観測はまだ行っていない。
- Codexの会話実行時のHook呼び出し。信頼済みとしての読み込みとHook処理の直接実行まで確認しており、モデルへの検証会話送信は承認待ち。
- Claude Codeでの読み込みと、仕事用Macへの実際の適用。
- もう一台の設定差分と、各MacにあるPython/Gitの配置。
- 実際に使うHookと実行環境。例は外部通信・ファイル変更のない単独Pythonスクリプト。
- ロックに協調しないアプリとの同時編集や、すべてのOS・ディスク障害を完全に防ぐ仕組みではない。

初回適用前に[導入手順と変更対象](MAC_INSTALL.md)を確認し、各Macの具体的な差分を承認してから設定する。
