## 1. 段階的な移行順序

既存の CLI を捨てる必要はない。
以下の優先順位で段階的にエージェント対応を追加する。

### Phase 1: 基礎（必須）

| # | 項目 | 説明 |
|---|------|------|
| 1 | `--output json` の追加 | 機械可読な出力は最低限の要件 |
| 2 | 全入力のバリデーション | 制御文字、パス走査、クエリパラメータ埋め込みを拒否。入力は常に敵対的と想定 |

### Phase 2: 拡張

| # | 項目 | 説明 |
|---|------|------|
| 3 | `--describe` コマンドの追加 | CLI が受け付けるパラメータのスキーマをランタイムで返す |
| 4 | Field masks / `--fields` のサポート | レスポンスサイズを制限し、コンテキストウィンドウを保護 |

### Phase 3: 安全機構

| # | 項目 | 説明 |
|---|------|------|
| 5 | `--dry-run` の追加 | 変更操作の事前検証を可能にする |
| 6 | CONTEXT.md / スキルファイルの同梱 | エージェントが `--help` からは推論できない不変条件を明文化 |

### Phase 4: 高度な統合

| # | 項目 | 説明 |
|---|------|------|
| 7 | MCP サーフェスの公開 | API をラップする CLI の場合、JSON-RPC ツールとして stdio 経由で公開 |

## 2. よくある質問

### CLI を一から書き直す必要があるか

**いいえ。** ほとんどのパターンは段階的に追加できる。
`--output json` と入力バリデーションから始めて、
スキーマイントロスペクションやスキルファイルを
レイヤーとして追加していく。

### REST API をラップしていない CLI の場合は

原則は同じ。エージェントが呼び出す全ての CLI は、
機械可読な出力、入力のハードニング、
不変条件の明示的なドキュメント化が必要。
スキーマイントロスペクションは API バックド CLI で
最も価値が高いが、`--describe` や `--help --json` は
どんな CLI にも適用できる。

### エージェント向けの認証はどう扱うか

- トークンや認証情報ファイルパスは**環境変数**で
- **サービスアカウント**を可能な限り使用
- ブラウザリダイレクトが必要なフローは避ける

### MCP は投資に値するか

CLI が構造化された API をラップしている場合、**はい**。
MCP はシェルエスケープ、引数パースの曖昧さ、
出力パースを排除する。
エージェントは文字列を組み立てるのではなく、
型付き関数を呼び出すだけになる。

### CLI がエージェントセーフかどうかテストするには

エージェントが犯す種類のミスで入力をファジングする:

- パス走査（`../../.ssh`）
- クエリパラメータ埋め込み（`id?fields=name`）
- 二重エンコード文字列（`%2e%2e`）
- 制御文字（ASCII 0x20 未満）

`--dry-run` で API に到達する前に
問題を検出できることを確認する。

## 3. 判定フローチャート

```text
既存 CLI がある
  |
  +-- stdout は JSON を返せるか?
  |     |
  |     +-- No --> --output json を追加（Phase 1）
  |     +-- Yes
  |           |
  +-- 入力バリデーションはあるか?
  |     |
  |     +-- No --> バリデーション追加（Phase 1）
  |     +-- Yes
  |           |
  +-- スキーマを返せるか?
  |     |
  |     +-- No --> --describe 追加（Phase 2）
  |     +-- Yes
  |           |
  +-- dry-run はあるか?
  |     |
  |     +-- No --> --dry-run 追加（Phase 3）
  |     +-- Yes
  |           |
  +-- エージェント向けドキュメントはあるか?
  |     |
  |     +-- No --> CONTEXT.md / Skill 追加（Phase 3）
  |     +-- Yes
  |           |
  +-- MCP 対応は必要か?
        |
        +-- API ラッパー --> MCP 公開（Phase 4）
        +-- それ以外 --> 完了
```

## 4. 本プロジェクトのスクリプトへの適用

`scripts/cli/` のスクリプトは
Claude Code エージェントから頻繁に呼び出される。
以下の観点で既存スクリプトを評価し、改善を検討する。

| 観点 | 確認項目 |
|------|---------|
| 出力の構造化 | JSON 出力オプションがあるか。exit code は適切か |
| 入力バリデーション | パス検証、制御文字拒否をしているか |
| コンテキスト制御 | 不要な出力を抑制しているか |
| 安全機構 | 破壊的操作に確認ステップがあるか |
| ドキュメント | SKILL.md にエージェント向けガイダンスがあるか |
