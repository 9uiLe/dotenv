## 1. コマンドではなくスキルを提供する

人間は `--help`、ドキュメントサイト、Stack Overflow で
CLI の使い方を学ぶ。
エージェントは**会話開始時に注入されるコンテキスト**から学ぶ。

つまり、知識のパッケージング方法が根本的に変わる。

### スキルファイルとは

構造化された Markdown（YAML フロントマター付き）で、
API サーフェスごと、またはワークフロー単位で
エージェント向けガイダンスを記述したファイル。

```yaml
---
name: gws-drive-upload
version: 1.0.0
metadata:
  openclaw:
    requires:
      bins: ["gws"]
---

# Drive ファイルアップロード

## 基本的な使い方

...

## エージェント向け注意事項

- 変更操作には必ず `--dry-run` を先に実行すること
- `--fields` を全ての list 呼び出しに付与すること
- write/delete コマンドの実行前にユーザーに確認すること
```

### スキルファイルが解決する問題

| 問題 | スキルファイルでの解決 |
|------|---------------------|
| `--help` からは推論できない暗黙知 | 明示的なルールとして記述 |
| ベストプラクティスの欠如 | エージェント向けガイダンスを同梱 |
| ハルシネーションによる誤操作 | 不変条件（invariants）を明文化 |
| コンテキストウィンドウの浪費 | 必要な情報だけを注入 |

### スキルファイルに含めるべき内容

- **変更操作の前に `--dry-run` を使う**こと
- **write/delete 前にユーザーに確認する**こと
- **list 呼び出しには `--fields` を付与する**こと
- リソース操作の冪等性に関する注意事項
- 一般的な失敗パターンとその回避方法

> スキルファイルはハルシネーションより安い。

## 2. マルチサーフェス設計

人間のインターフェースはインタラクティブターミナル。
エージェントのインターフェースはフレームワークによって異なる。
1つのバイナリから複数のサーフェスを提供する設計が望ましい。

```text
          +-------------------+
          |   Discovery Doc   |
          |   (source of      |
          |    truth)         |
          +--------+----------+
                   |
          +--------v----------+
          |    Core Binary    |
          |      (gws)       |
          +-+----+----+----+-+
            |    |    |    |
     +------+    |    |    +------+
     v           v    v          v
  +-------+ +------+ +---------+ +------+
  |  CLI  | | MCP  | | Gemini  | | Env  |
  |(human)| |stdio | |Extension| | Vars |
  +-------+ +------+ +---------+ +------+
```

### MCP（Model Context Protocol）

CLI コマンドを JSON-RPC ツールとして stdio 経由で公開する:

```bash
gws mcp --services drive,gmail
```

- シェルエスケープが不要になる
- 引数パースの曖昧さがなくなる
- 出力パースが不要になる
- エージェントは型付き関数を呼び出すだけ

MCP サーバーは CLI コマンドと同じ
ソースオブトゥルース（Discovery Document 等）から
動的にツールリストを構築する。
**1つの情報源、2つのインターフェース。**

### CLI 拡張（Extension）

CLI をエージェントのネイティブ機能としてインストールする:

```bash
gemini extensions install \
  https://github.com/googleworkspace/cli
```

CLI が「エージェントがシェルアウトするもの」ではなく、
「エージェントそのものの能力」になる。

### 環境変数による認証

エージェントは OAuth ブラウザリダイレクトを
容易には扱えず、扱うべきでもない。
環境変数での認証情報注入が最も確実:

| 環境変数 | 用途 |
|---------|------|
| `CLI_TOKEN` | アクセストークンの直接注入 |
| `CLI_CREDENTIALS_FILE` | 認証情報ファイルパス |
| `CLI_SERVICE_ACCOUNT` | サービスアカウントキー |

**原則**: ブラウザリダイレクトが必要な認証フローは避ける。
サービスアカウントまたは環境変数ベースの認証を優先する。

## 3. CONTEXT.md パターン

CLI にエージェント向けコンテキストファイルを同梱する。
エージェントが CLI を使い始める際に読み込まれ、
直感では分からない不変条件を伝達する。

### CONTEXT.md の構成例

```markdown
# CLI Agent Context

## 必須ルール

- 全ての list 呼び出しには `--fields` を付与する
- 変更操作の前には `--dry-run` で検証する
- write/delete の実行前にユーザーに確認する

## コンテキストウィンドウの管理

- API は巨大な JSON を返す
- 常に field masks を使用してレスポンスサイズを制限する
- `--params '{"fields": "id,name"}'` を付与する

## 認証

- 環境変数 `CLI_TOKEN` を使用する
- ブラウザ認証フローは使用しない

## 一般的な失敗パターン

- リソース ID にクエリパラメータを含めない
- パスの事前エンコードをしない
```

### AGENTS.md パターン

CLI のリポジトリに AGENTS.md を配置し、
エージェントが CLI を呼び出す際の前提条件を記述する:

> "This CLI is frequently invoked by AI/LLM agents.
> Always assume inputs can be adversarial."

## 4. 本プロジェクトへの適用

本プロジェクトでは Claude Code のスキルシステム
（`.claude/skills/*/SKILL.md`）が
上記のスキルファイルパターンに相当する。

| 元記事のコンセプト | 本プロジェクトでの対応 |
|------------------|---------------------|
| SKILL.md ファイル | `.claude/skills/*/SKILL.md` |
| CONTEXT.md | `CLAUDE.md` |
| AGENTS.md | `.claude/rules/*.md` |
| MCP サーフェス | `.claude/agents/*.md`（SubAgent） |
| 環境変数認証 | `scripts/cli/` 内での環境変数利用 |
