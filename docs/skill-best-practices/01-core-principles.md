## 1. 簡潔さが鍵

SKILL.md は **500行以下** を目標とする。Claude が既に知っている一般的な知識（言語の文法、標準ライブラリの使い方など）は省略し、**プロジェクト固有の情報** に集中する。

### 良い例

```markdown
## 命名規則

- スクリプト名: ケバブケース（例: `build-verify`, `snapshot-preview`）
- 配置場所: `scripts/cli/`
```

### 悪い例

```markdown
## 命名規則

シェルスクリプトの命名には様々な方法があります。キャメルケース、スネークケース、ケバブケースなどがあります。
キャメルケースは各単語の先頭を大文字にする方法です（例: buildVerify）。
スネークケースは単語をアンダースコアで区切る方法です（例: build_verify）。
本プロジェクトではケバブケースを採用しています...
```

## 2. 適切な自由度

タスクの性質に応じて、スキルが Claude に与える自由度を調整する。

| 自由度 | 適用場面 | スキル内での表現 |
|--------|---------|-----------------|
| **高** | 新規コンテンツの生成、設計判断 | 「以下の観点を考慮して最適な方法を選択」 |
| **中** | 既存パターンの適用、バリエーション | 「以下のテンプレートをベースに、要件に合わせて調整」 |
| **低** | 定型処理、構文の厳密な準拠 | 「以下のテンプレートに正確に従う。変更不可」 |

### プロジェクトでの適用例

| スキル | 自由度 | 理由 |
|--------|--------|------|
| script-creator | 中 | テンプレートベースだが複雑度で分岐 |
| (例: commit) | 低 | セルフレビュー + 品質チェックの定型フロー |
| (例: plan-tools) | 中 | 要件チェックリストで不足時のみ質問 |

## 3. 段階的開示

SKILL.md には **概要と実行フロー** を記載し、詳細なテンプレートや例は **別ファイル** に分離する。ただし、参照は **1レベル深いまで** とする。

### 推奨構造

```text
.claude/skills/my-skill/
├── SKILL.md          # 概要 + 実行フロー（メインファイル）
├── reference.md      # 詳細テンプレート、出力フォーマット（1レベル深い）
└── examples.md       # 実行例、エラー対応（1レベル深い）
```

### 避けるべき構造

```text
.claude/skills/my-skill/
├── SKILL.md
├── reference.md
│   └── (reference.md 内で templates/detail.md を参照)  # NG: 2レベル深い
└── templates/
    └── detail.md     # NG: SKILL.md から直接参照できない深さ
```

### 長い参照ファイルの構造化

100行以上の参照ファイルには、上部に目次を含める。これにより部分的な読み取り時でも全体構成を把握できる。

## 4. 効果的な説明文（description）

フロントマターの `description` はスキルの発見性に直結する。以下のルールに従う。

### ルール

- **三人称で書く**: 「〇〇します」（主語は省略）
- **トリガーワードを含む**: ユーザーがどのような言葉でスキルを呼び出すかを意識
- **具体的な機能を列挙**: 抽象的な説明ではなく、何ができるかを明示

### 良い例

```yaml
description: scripts/cli/ 配下のシェルスクリプトをガイド付きで作成します。対話的な要件収集、ベストプラクティス参照、テンプレート生成、品質検証、連携登録までをカバーします。
```

### 悪い例

```yaml
description: スクリプトを作成するスキルです。
```

## 5. ワークフローとフィードバックループ

スキルの実行フロー内に **検証ステップ** を組み込み、品質を保証する。

### 推奨パターン

```text
実行 → 検証 → (問題あれば修正 → 再検証) → 完了
```

### プロジェクトでの適用例

| スキル | 検証ステップ |
|--------|-------------|
| script-creator | shellcheck 実行 + メタデータ完備チェック + agent-friendly 観点チェック |
| (例: commit) | diff-review + Hooks（check-diff 自動実行） |
| (例: plan-tools) | claude-instruction-reviewer で設定ファイル検証 |

---

## 6. 一貫した用語

スキル全体で用語を統一する。同じ概念に異なる名称を使用しない。

### プロジェクトの標準用語

| 用語 | 意味 | 使用しない表現 |
|------|------|---------------|
| スキル (Skill) | `.claude/skills/*/SKILL.md` | プラグイン、コマンド |
| エージェント (Agent) | `.claude/agents/*.md` | サブエージェント、ワーカー |
| ルール (Rule) | `.claude/rules/*.md` | ポリシー、制約 |
| フロントマター | YAML ヘッダー（`---` で囲まれた部分） | メタデータ、ヘッダー |
| SubAgent | Task() で呼び出す Agent | 子プロセス、ヘルパー |
