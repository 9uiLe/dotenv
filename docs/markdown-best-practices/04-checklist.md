## 新規ドキュメント作成チェックリスト

### 見出し

- [ ] ATX スタイル（`#`）を使用している
- [ ] H1 はドキュメントあたり1つのみ
- [ ] 見出しの前後に空行がある
- [ ] `#` の後にスペースがある
- [ ] 見出しレベルを飛ばしていない（H2 → H4 など）
- [ ] 見出し名が説明的でユニーク
- [ ] 同一ドキュメント内で重複する見出し名がない

### テキストスタイル

- [ ] 太字・イタリックにアスタリスク（`*`）を使用している（アンダースコア不可）
- [ ] コード、コマンド、ファイルパスにインラインコード（`` ` ``）を使用している
- [ ] 強調の使い分けが適切（太字: 重要語、イタリック: 補足、コード: 技術用語）

### リスト

- [ ] 順序なしリストにハイフン（`-`）を使用している
- [ ] ネストリストに4スペースインデントを使用している
- [ ] 長い順序付きリストで lazy numbering（全て `1.`）を使用している
- [ ] リストの前後に空行がある

### コードブロック

- [ ] フェンス形式（`` ``` ``）を使用している
- [ ] 言語識別子を指定している（`swift`, `yaml`, `bash` 等）
- [ ] インデントによるコードブロックを使用していない
- [ ] 長いコマンドラインはバックスラッシュ（`\`）で改行している

### テーブル

- [ ] 均一データの比較・一覧にのみテーブルを使用している
- [ ] ヘッダー行と区切り行がある
- [ ] テーブルの前後に空行がある
- [ ] セルに長い文章を入れていない

### リンク

- [ ] 説明的なリンクテキストを使用している（「こちら」は不可）
- [ ] 同一リポジトリ内は相対パスを使用している
- [ ] URL の直接記載を避けている
- [ ] 長い URL には参照リンクスタイルを使用している

### 画像

- [ ] 画像の使用が必要最小限か確認した（テキストで代替できないか）
- [ ] 代替テキスト（alt text）を記載している

### ドキュメント構造

- [ ] 先頭に H1 タイトルがある
- [ ] タイトル直後に導入文がある
- [ ] セクションが論理的に構成されている

### フォーマット

- [ ] 末尾の空白がない
- [ ] ファイル末尾に改行がある
- [ ] HTML タグを使用していない（Markdown 構文を優先）
- [ ] 1行80文字を目安にしている（リンク、テーブル、見出し、コードブロックは例外）
- [ ] 改行にバックスラッシュ（`\`）を使用している（末尾2スペースは不可）

## docs/ ガイド固有チェックリスト

### README.md

- [ ] 概要セクションがある
- [ ] 対象読者セクションがある
- [ ] ドキュメント一覧テーブルがある
- [ ] テーブルのリンクが正しい

### チャプターファイル

- [ ] `[← 目次に戻る](./README.md)` バックリンクがある
- [ ] バックリンクの後に区切り線（`---`）がある
- [ ] セクションに番号が付いている（`## 1. ...`, `## 2. ...`）
- [ ] 大きなセクション間に区切り線がある

## 既存ドキュメント改善チェックリスト

### 構造の改善

- [ ] 見出しレベルが適切か（飛ばしがないか）
- [ ] 長すぎるセクションを分割すべきか
- [ ] テーブルに長い文章が入っていないか

### 一貫性の改善

- [ ] 同じドキュメント内でリスト記号が統一されているか
- [ ] 強調スタイルが統一されているか（アスタリスクに統一）
- [ ] コードブロックの言語指定が統一されているか

### リンクの改善

- [ ] リンク切れがないか
- [ ] 「こちら」等の曖昧なリンクテキストがないか
- [ ] 絶対パスを相対パスに変更すべきか
