## 1. 基本構造

### ドキュメントの標準構成

```markdown
# タイトル（H1 は1つだけ）

導入文（1-2文でドキュメントの目的を説明）

## セクション 1

本文...

## セクション 2

本文...
```

### H1 はドキュメントあたり1つ

ドキュメントの先頭に H1（`#`）を1つだけ配置する。以降のセクションは H2（`##`）以下を使用する。

```markdown
<!-- Good -->
# ガイドタイトル

## セクション A

## セクション B

<!-- Bad（H1 が複数） -->
# ガイドタイトル

# セクション A

# セクション B
```

## 2. 見出しの命名

### 説明的でユニークな見出し名

見出しはアンカーリンクの生成元になるため、説明的でユニークな名前を付ける。

```markdown
<!-- Good（説明的でユニーク） -->
## ビルドの前提条件
## テストの実行手順
## デプロイの設定

<!-- Bad（曖昧、重複の可能性） -->
## 概要
## 設定
## 手順
```

### 重複する見出しを避ける

複数セクションで同じ見出し名（「概要」「例」等）を使うと、アンカーリンクが曖昧になる。親セクション名を含めて一意にする。

```markdown
<!-- Good（親セクション名を含めて一意） -->
## Foo
### Foo の概要
### Foo の例
## Bar
### Bar の概要
### Bar の例

<!-- Bad（見出し名が重複） -->
## Foo
### 概要
### 例
## Bar
### 概要
### 例
```

### 見出しにコードを含む場合

見出しにコードを含める場合はバッククォートを使用する。

```markdown
## `CLAUDE.md` の更新方法
## `swift build` のオプション
```

## 3. プロジェクト固有の構造パターン

### docs/ ガイドの構造

`docs/` 配下のガイドは以下の構造に従う。

```
docs/<topic>/
├── README.md          # 概要、ドキュメント一覧テーブル
├── 01-<name>.md       # チャプター 1
├── 02-<name>.md       # チャプター 2
├── 03-<name>.md       # チャプター 3
└── 04-<name>.md       # チャプター 4（必要に応じて）
```

#### README.md の構成

| セクション | 内容 |
|-----------|------|
| H1 タイトル | ガイド名 |
| 概要 | ガイドの目的と範囲 |
| 対象読者 | どのような場面で参照するか |
| ドキュメント一覧 | ファイルと内容のテーブル |

#### チャプターファイルの構成

| セクション | 内容 |
|-----------|------|
| H1 タイトル | チャプター名 |
| バックリンク | `[← 目次に戻る](./README.md)` |
| 区切り線 | `---` |
| 本文 | 番号付きセクション（`## 1. ...`, `## 2. ...`） |

```markdown
<!-- チャプターファイルの冒頭テンプレート -->
# チャプタータイトル

[← 目次に戻る](./README.md)

---

## 1. 最初のセクション

...
```

### Rule ファイルの構造

`.claude/rules/*.md` は以下の構成に従う。

```markdown
---
paths: <glob-pattern>
---

# ルール名

## 概要

ルールの目的と、カバーする範囲の説明。

## 必須手順

### 参照すべきドキュメントの選択

| 作業内容 | 参照ドキュメント | パス |
|---------|----------------|------|
| ... | ... | ... |

### 参照方法

1. テーブルから該当ドキュメントを特定
2. Read で読み込む
3. パターンに従って実装

### 全体像の把握が必要な場合

README.md への誘導。

## 理由

ルールが必要な理由。
```

### Agent ファイルの構造（レビュー系）

`.claude/agents/*-reviewer.md` は以下の構成に従う。

```markdown
---
name: <agent-name>
description: <説明文>
tools: Read, Grep, Glob
model: haiku
---

# <agent-name> Sub Agent

1行の概要。

## 目的

レビューの目的。

## レビュー観点

### 1. 観点名

説明と Bad/Good 例。

### 2. 観点名

説明と Bad/Good 例。

## 実行手順

### 1. 差分の取得
### 2. レビュー実行
### 3. 結果の分類

## 返却するサマリー

サマリーフォーマット。
```
